How to use this plan

You already understand explanations. What you are building now is the ability to start a problem on your own and still remember it a week later. This plan trains exactly those two things.

Every study day has four steps (about 45–60 minutes)

  1. Warm up (10 min). Read a topic sheet, trace an example on paper, or solve an easy problem from this booklet.
  2. Namaste DSA lesson (15–20 min). Watch the lesson(s) named for the day.
  3. Solve on your own (15 min). Solve the practice problem in your editor or browser console. Wait 5 minutes before reading Hint 1. Read hints one at a time.
  4. Close (2 min). Without looking, write today's key idea in one sentence in a notebook.

Words used in the plan

  • Try first: attempt the problem for 10–15 honest minutes before watching the lesson. Getting stuck is the point. The lesson then answers a question you already have, so it sticks.
  • Re-solve from memory: blank file, no hints, no peeking. If you can't, read the solution once and try again in two days. That is still progress.
  • ★ core: short on time? Do only the core steps (about 30 minutes). A short day beats a skipped day.

Remembering (so you don't forget after 4–5 days)

After you solve a problem, write its number and date on the tracker page at the back. Re-solve it from memory 1, 3, 7 and 14 days later. If it went well, push the next one further out. If you couldn't, go back to a 1-day gap. Every 5th day in the plan is a review day for this.

How to practise without the app

Write each solution as a function in a .js file and test it with the examples:

function sumTo(n) { /* your code */ }
console.log(sumTo(4), "expected 10");
console.log(sumTo(0), "expected 0");

Run it with node file.js or paste it into the browser console. Always also test the edge cases: empty input, one element, all equal, negative numbers.

Rules that keep you honest. Watching a video or reading a solution is not the same as being able to do it. A problem counts as "mine" only when you solve it from a blank file, from memory, days later. Missing a day never puts you behind: the days are numbered, not dated, so just do the next one.

T1. Loops & Number Logic

Namaste module 2

Make the computer repeat a small, clear step.

Almost every DSA solution is a loop that repeats one small decision. If you can describe that one step in plain words, the loop writes itself.

For number problems, n % 10 gives the last digit and Math.floor(n / 10) drops it. Repeat until the number is 0 and you have visited every digit.

Analogy. Peeling a stack of plates: look at the top plate (n % 10), do something with it, remove it (Math.floor(n / 10)), and stop when no plates remain.

Key idea. Decide: what changes each step, what you keep track of, and when you stop.

When you see… think of…

  • "digits of a number" → loop with % 10 and / 10
  • "for every element" → one loop over the input
  • "every pair" → loop inside a loop

Complexity. One loop over n items is O(n). A loop inside a loop over the same items is O(n²). Digit loops are O(number of digits).

T2. Time & Space Complexity

Namaste module 3

How does the work grow when the input grows?

Big-O ignores exact timings and asks one question: if the input doubles, roughly how much more work happens?

Count the loops that depend on n. One loop: O(n). Nested loops over n: O(n²). Halving the range each step: O(log n).

Analogy. Finding a name in a phone book: reading every page is O(n); opening in the middle and discarding half each time is O(log n).

Key idea. Count how many times the innermost line runs as a function of n.

When you see… think of…

  • "input up to 10⁵" → you need about O(n log n) or better
  • "halve the search space" → O(log n)
  • "extra array/map of size n" → O(n) space

Complexity. Drop constants and smaller terms: O(2n + 5) is O(n).

Predict the output (answer before you run anything):

1. Time complexity?

    }
  }
}

  while (n > 1) {
    n = Math.floor(n / 2);
    steps++;
  }
  return steps;

Options: (a) O(n) (b) O(log n) (c) O(n²) (d) O(√n)

3. Extra space complexity?

  const seen = new Set();
  for (const x of arr) seen.add(x);
  return seen.size;

Options: (a) O(1) (b) O(n) (c) O(log n) (d) O(n²)

Answers: 1. (c) For each of n values of i, the inner loop runs n times: n × n. 2. (b) n is halved every step, so the loop runs about log₂(n) times. 3. (b) In the worst case every element is distinct and the Set stores all n of them.

Most easy array problems are one pass where you carry a few variables: the best so far, a count, a running sum.

Before coding, ask: "If I could only remember one or two numbers while walking left to right, which numbers would they be?"

T4. Two Pointers

Namaste module 4, 8, 11

Two indexes moving with purpose instead of checking every pair.

Checking every pair costs O(n²). Two pointers often get the same answer in O(n) because each pointer only moves forward (or inward).

Two common shapes: opposite ends moving inward (palindromes, sorted pair sums), and slow/fast moving the same way (removing or compacting elements in place).

Analogy. Two people reading a word from both ends toward the middle, comparing letters as they go. They meet in the middle having done half the work each.

Key idea. Each step, use a comparison to decide which pointer moves. Never move both blindly.

When you see… think of…

  • "sorted array" + "pair" → left/right pointers
  • "in place" + "remove/move" → slow (write) and fast (read) pointers
  • "palindrome" → compare from both ends

Complexity. Each pointer moves at most n times, so the whole loop is O(n) with O(1) extra space.

T5. Recursion Basics

Namaste module 5

Solve a small piece, trust the function for the rest.

A recursive function answers a big question by asking itself a smaller version of the same question, plus a base case that answers the tiniest version directly.

Do not trace every call in your head. Write: "If f(n - 1) is already correct, how do I build f(n) from it?"

Analogy. Russian nesting dolls: to count the dolls, open one, count 1, and ask the doll inside to count itself. The smallest doll just says 1.

Key idea. Base case + one step that shrinks the problem + combine.

When you see… think of…

  • "defined in terms of a smaller version" (factorial, sum of n) → recursion
  • "trees / nested structures" → recursion is natural
  • Every recursive call must move toward the base case

Complexity. A function that calls itself once per level with n levels is O(n) time and O(n) call-stack space.

Throw away half of the possibilities every step.

Most bugs are boundary bugs. Pick one convention (we use while (lo <= hi)) and stick with it.

Analogy. Guessing a number between 1 and 100 when someone says "higher" or "lower". Guessing 50 first eliminates half the numbers in one question.

Key idea. Keep [lo, hi] as the range where the answer can still be. Shrink it using the middle.

  • "sorted" + "find" → binary search
  • "smallest x such that..." with a yes/no check → binary search on the answer

T7. Strings

Namaste module 8

Strings are arrays of characters with extra rules.

Treat a string like a read-only array: s[i], s.length, loop over it. JavaScript strings are immutable, so build results in an array or a new string.

  • "reads the same backward" → two pointers

Remember what you have seen, look it up in O(1).

A Map or Set lets you answer "have I seen this before?" or "how many times?" instantly, trading memory for speed.

The classic upgrade: a nested loop that searches for a partner becomes one loop that asks the map whether the partner already appeared.

Analogy. A coat check: you hand in a coat and get a ticket. Later you find the coat instantly by its ticket instead of searching every rack.

Key idea. Decide the key (what you look up) and the value (what you need back).

When you see… think of…

  • "count occurrences / frequency" → Map from item to count
  • "seen before / duplicate" → Set
  • "find a pair that sums to target" → Map from value to index

Complexity. Map/Set lookups are O(1) on average, so one pass with a map is O(n) time and O(n) space.

T9. Sliding Window

Namaste module 11

Reuse the work from the previous window instead of starting over.

For "contiguous subarray / substring" problems, a window [left, right] slides across the input. When it moves, add what enters and remove what leaves.

Fixed-size windows move both ends together. Variable windows grow on the right and shrink on the left when a rule breaks.

Analogy. Looking through a train window: as the train moves, one new tree appears on the right and one disappears on the left. You do not re-count the whole view.

Key idea. Maintain a summary of the window (sum, counts) and update it in O(1) per move.

When you see… think of…

  • "contiguous subarray of size k" → fixed window
  • "longest substring such that..." → variable window + map/set
  • Brute force checks every subarray (O(n²)) → window makes it O(n)

Complexity. Each element enters and leaves the window at most once: O(n) time.

Predict the output (answer before you run anything):

1. What gets logged?

let sum = a[0] + a[1] + a[2];
sum = sum - a[0] + a[3];
console.log(sum);

2. What is l at the end?

const seen = new Set();
let l = 0;
for (let r = 0; r < s.length; r++) {
  while (seen.has(s[r])) seen.delete(s[l++]);
  seen.add(s[r]);
}
console.log(l);

Options: (a) 0 (b) 1 (c) 2 (d) 3

Answers: 1. (b) Window [2,1,5]=8 slides to [1,5,1]: 8 - 2 + 1 = 7. 2. (b) When the second "a" arrives, the window drops the first "a" and l moves to 1.

Hash Maps & Sets · level 5

Return indexes [i, j] with i < j such that nums[i] + nums[j] === target. Exactly one answer exists. The array is not sorted. Aim for O(n).

Write: function twoSum(…)

Input: nums = [3, 5, 2, 8], target = 7 → Output: [1, 2] (5 + 2 = 7)

Constraints: 2 ≤ nums.length ≤ 10⁴. Edge cases to test: duplicate values ([3, 3]); negative numbers.

Hints (read one at a time, only after 5 minutes of trying):

  1. For a number x, what partner value would complete the pair?
  2. The partner is target − x. The question becomes: "have I already seen target − x?"
  3. Store each value with its index in a Map as you go. Check the map before inserting the current value.
  4. Pseudocode: seen←Map; for i: need←t−nums[i]; if seen has need return [seen[need], i]; seen[nums[i]]←i.

P29. Pair With Target (Sorted)

Two Pointers · level 4

nums is sorted ascending. Return the indexes [i, j] (i < j) of two numbers that add up to target, or [-1, -1] if no pair exists. Use O(1) extra space.

Write: function pairSumSorted(…)

Input: nums = [1, 3, 4, 6, 8, 11], target = 10 → Output: [2, 3] (4 + 6)

Constraints: 2 ≤ nums.length ≤ 10⁴; At most one valid pair.. Edge cases to test: no pair; negative numbers; pair at the two ends.

Hints (read one at a time, only after 5 minutes of trying):

  1. Start with the smallest and largest numbers. If their sum is too big, which one should you drop?
  2. Too big → move the right pointer left (smaller number). Too small → move the left pointer right.
  3. Stop when the sum matches or the pointers meet.
  4. Pseudocode: l←0, r←n−1; while l<r: s←nums[l]+nums[r]; if s==t return [l,r]; if s<t l++ else r--; return [-1,-1].

P30. Best Window of Size K

Return the largest sum of any k consecutive elements of nums.

Write: function maxSumK(…)

Input: nums = [2, 1, 5, 1, 3, 2], k = 3 → Output: 9 ([5, 1, 3])

Constraints: 1 ≤ k ≤ nums.length ≤ 10⁵. Edge cases to test: k equals the array length; all negative numbers.

Hints (read one at a time, only after 5 minutes of trying):

  1. The brute force recomputes each window's sum from scratch. How do neighbouring windows differ?
  2. Moving the window one step right adds one new element and removes one old element.
  3. Compute the first window's sum. Then for i from k: sum += nums[i] − nums[i − k], and track the best.
  4. Pseudocode: sum←Σ nums[0..k−1]; best←sum; for i in k..n−1: sum←sum+nums[i]−nums[i−k]; best←max(best,sum); return best.

P1. Sum from 1 to N

Accumulator loop
function sumTo(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) {
    total += i;
  }
  return total;
}

Keep a running total and add each number once. (There is also the formula n(n+1)/2, but the loop is the skill being practised.)

Complexity: O(n) time, O(1) space. One loop of n steps and a single number of state.

Common mistakes: Using i < n and missing n itself; Forgetting to return the total.

P2. Count Greater Than X

Single pass with a counter
function countGreater(nums, x) {
  let count = 0;
  for (const v of nums) {
    if (v > x) count++;
  }
  return count;
}

A counter is just an accumulator that adds 1 when a condition holds.

Complexity: O(n) time, O(1) space. One pass, one counter.

Common mistakes: Using >= instead of >.

P3. Largest Element

Single pass with a tracker
function findMax(nums) {
  let best = nums[0];
  for (const x of nums) {
    if (x > best) best = x;
  }
  return best;
}

Track the best value seen so far. Starting from nums[0] avoids the all-negative trap.

Complexity: O(n) time, O(1) space. Each element is looked at once.

Common mistakes: Starting best at 0; Returning inside the loop.

P4. Second Largest Distinct

Single pass with two trackers
function secondLargest(nums) {
  let first = -1, second = -1;
  for (const x of nums) {
    if (x > first) {
      second = first;
      first = x;
    } else if (x > second && x !== first) {
      second = x;
    }
  }
  return second;
}

When a new maximum appears, the old maximum becomes the second. Duplicates of the max are skipped so the answer stays distinct.

Complexity: O(n) time, O(1) space. One pass with two variables.

Common mistakes: Forgetting to move first into second; Allowing a duplicate of the max as second.

P5. Count the Digits

Digit peeling (% 10, / 10)
function countDigits(n) {
  if (n === 0) return 1;
  n = Math.abs(n);
  let count = 0;
  while (n > 0) {
    n = Math.floor(n / 10);
    count++;
  }
  return count;
}

Dividing by 10 and flooring drops the last digit. Count drops until nothing is left. 0 is handled up front because the loop would not run.

Complexity: O(d) time, O(1) space. d = number of digits, about log₁₀(n).

Common mistakes: Returning 0 for n = 0; Using n / 10 without Math.floor (gives decimals, loops for a long time); Infinite loop for negatives.

P6. Reverse a Number

Digit peeling + building
function reverseNumber(n) {
  const sign = n < 0 ? -1 : 1;
  n = Math.abs(n);
  let rev = 0;
  while (n > 0) {
    rev = rev * 10 + (n % 10);
    n = Math.floor(n / 10);
  }
  return sign * rev;
}

Peel digits from the right and push them onto the right of rev. Multiplying rev by 10 makes room for the next digit.

Complexity: O(d) time, O(1) space. One iteration per digit.

Common mistakes: Losing the sign; Using % on a negative number (gives negative digits).

P7. Palindrome Number

Reverse and compare
function isPalindromeNumber(n) {
  if (n < 0) return false;
  let x = n, rev = 0;
  while (x > 0) {
    rev = rev * 10 + (x % 10);
    x = Math.floor(x / 10);
  }
  return rev === n;
}

Reuse the reverse-number idea on a copy, then compare with the original.

Complexity: O(d) time, O(1) space. One pass over the digits.

Common mistakes: Reversing n itself and then comparing with the destroyed value — copy n first.

P8. Reverse an Array In Place

Opposite-end pointers + swap
function reverseInPlace(arr) {
  let l = 0, r = arr.length - 1;
  while (l < r) {
    [arr[l], arr[r]] = [arr[r], arr[l]];
    l++;
    r--;
  }
  return arr;
}

Two pointers start at opposite ends and swap their way to the middle. The middle element of an odd-length array stays put.

Complexity: O(n) time, O(1) space. n/2 swaps, no extra array.

Common mistakes: Looping the full length (reverses twice, back to the original); Using arr.reverse() — fine in real life, but practise the pointers.

P9. Compact a Sorted Array

Slow (write) + fast (read) pointers
function compactSorted(nums) {
  if (nums.length === 0) return 0;
  let w = 1;
  for (let r = 1; r < nums.length; r++) {
    if (nums[r] !== nums[w - 1]) nums[w++] = nums[r];
  }
  return w;
}

Sorted order puts duplicates side by side, so comparing with the last kept value is enough.

Complexity: O(n) time, O(1) space. Single pass with two indexes.

Common mistakes: Comparing with nums[r - 1] after overwriting (works here, but compare with the last kept value to be safe); Not handling empty input.

P10. Zeros to the End

Slow (write) + fast (read) pointers
function zerosToEnd(nums) {
  let w = 0;
  for (let r = 0; r < nums.length; r++) {
    if (nums[r] !== 0) nums[w++] = nums[r];
  }
  for (let i = w; i < nums.length; i++) nums[i] = 0;
  return nums;
}

The write pointer compacts the non-zero values to the front in order. The rest is filled with zeros.

Complexity: O(n) time, O(1) space. Two linear passes, no extra array.

Common mistakes: Removing with splice inside a loop (skips elements, O(n²)).

P11. Best Single Trade

Track minimum so far
function bestProfit(prices) {
  let min = prices[0], best = 0;
  for (const p of prices) {
    if (p < min) min = p;
    if (p - min > best) best = p - min;
  }
  return best;
}

Fix the selling day and the best buying day is the minimum before it. Carrying the running minimum makes that O(1) per day.

Complexity: O(n) time, O(1) space. One pass with min and best.

Common mistakes: Taking global max − global min (the max may come before the min).

P12. Merge Two Sorted Lists of Numbers

One pointer per input
function mergeSorted(a, b) {
  const out = [];
  let i = 0, j = 0;
  while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) out.push(a[i++]);
    else out.push(b[j++]);
  }
  while (i < a.length) out.push(a[i++]);
  while (j < b.length) out.push(b[j++]);
  return out;
}

Two pointers walk the inputs in parallel. This is the merge step of merge sort.

Complexity: O(n + m) time, O(n + m) space. Each element is copied once into the output.

Common mistakes: Forgetting leftovers; Using sort() without a comparator (sorts as strings).

P13. Longest Run of Ones

Current streak + best streak
function longestOnes(bits) {
  let cur = 0, best = 0;
  for (const b of bits) {
    cur = b === 1 ? cur + 1 : 0;
    if (cur > best) best = cur;
  }
  return best;
}

The current streak resets on 0. Update best every step so a run that ends at the last element still counts.

Complexity: O(n) time, O(1) space. One pass, two counters.

Common mistakes: Only updating best when a 0 appears (misses runs at the end).

P14. The Missing Number

Expected sum minus actual sum
function missingNumber(nums) {
  const n = nums.length;
  let expected = (n * (n + 1)) / 2;
  for (const x of nums) expected -= x;
  return expected;
}

The gap between the full sum and the actual sum is exactly the missing value.

Complexity: O(n) time, O(1) space. One pass to subtract every value.

Common mistakes: Using nums.length - 1 as n; Assuming the array is sorted.

P15. Factorial, Recursively

Base case + smaller self-call
function factorial(n) {
  if (n === 0) return 1;
  return n * factorial(n - 1);
}

n! = n × (n−1)!, and 0! = 1 stops the recursion.

Complexity: O(n) time, O(n) space. n nested calls on the call stack.

Common mistakes: Missing base case → stack overflow; Base case returning 0 (makes everything 0).

P16. Sum an Array, Recursively

Recursion over an index
function sumArray(nums, i = 0) {
  if (i === nums.length) return 0;
  return nums[i] + sumArray(nums, i + 1);
}

Each call handles one element and delegates the rest. Passing an index avoids copying the array with slice.

Complexity: O(n) time, O(n) space. One call per element on the stack.

Common mistakes: Forgetting to pass nums along; Base case on i > n instead of i === n.

P17. Is It a Power of Two?

Recursive halving
function isPowerOfTwo(n) {
  if (n === 1) return true;
  if (n <= 0 || n % 2 !== 0) return false;
  return isPowerOfTwo(n / 2);
}

Keep halving. You reach exactly 1 only if every step was even.

Complexity: O(log n) time, O(log n) space. n halves every call.

Common mistakes: Infinite recursion on 0 (0 / 2 is still 0).

P18. Classic Binary Search

lo/hi/mid on sorted data
function binarySearch(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (nums[mid] === target) return mid;
    if (nums[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}

Each comparison discards half of the remaining range. mid ± 1 guarantees progress, so the loop always ends.

Complexity: O(log n) time, O(1) space. The search range halves every iteration.

Common mistakes: lo = mid instead of mid + 1 (infinite loop); while lo < hi (misses the last candidate).

P19. Count the Vowels

Character scan with a membership check
function countVowels(s) {
  const vowels = new Set(["a", "e", "i", "o", "u"]);
  let count = 0;
  for (const ch of s) {
    if (vowels.has(ch.toLowerCase())) count++;
  }
  return count;
}

Loop over characters and count those in the vowel set.

Complexity: O(n) time, O(1) space. The vowel set has a fixed size of 5.

Common mistakes: Forgetting uppercase.

P20. First Repeated Value

Seen-set
function firstRepeat(nums) {
  const seen = new Set();
  for (const x of nums) {
    if (seen.has(x)) return x;
    seen.add(x);
  }
  return -1;
}

The set remembers everything seen so far, so the first hit is the first repeat.

Complexity: O(n) time, O(n) space. The set may hold every element.

Common mistakes: Returning the value that repeats most, not first.

P21. Most Frequent Character

Frequency map
function mostFrequent(s) {
  const counts = new Map();
  for (const ch of s) counts.set(ch, (counts.get(ch) || 0) + 1);
  let best = s[0];
  for (const ch of s) {
    if (counts.get(ch) > counts.get(best)) best = ch;
  }
  return best;
}

Count first, decide second. Walking s in order for the decision makes "first in s" win ties.

Complexity: O(n) time, O(k) space. k distinct characters stored in the map.

Common mistakes: Iterating over the map and breaking ties by map order without thinking it through; Using >= (changes tie-breaking).

P22. Reverse Word Order

Split, transform, join
function reverseWords(s) {
  const words = s.trim().split(/\s+/);
  let l = 0, r = words.length - 1;
  while (l < r) {
    [words[l], words[r]] = [words[r], words[l]];
    l++;
    r--;
  }
  return words.join(" ");
}

Turn the string problem into an array problem, solve it with two pointers, then join back.

Complexity: O(n) time, O(n) space. The words array holds the whole string.

Common mistakes: Leaving empty strings from multiple spaces.

P23. Clean Palindrome Check

Opposite-end pointers with skipping
function isCleanPalindrome(s) {
  const ok = (c) => /[a-z0-9]/i.test(c);
  let l = 0, r = s.length - 1;
  while (l < r) {
    while (l < r && !ok(s[l])) l++;
    while (l < r && !ok(s[r])) r--;
    if (s[l].toLowerCase() !== s[r].toLowerCase()) return false;
    l++;
    r--;
  }
  return true;
}

Same inward walk as reversing, but each pointer first skips characters that should be ignored.

Complexity: O(n) time, O(1) space. Each pointer only moves inward.

Common mistakes: Forgetting l < r inside the skipping loops; Not lowercasing.

P24. Shared Starting Letters

Column-by-column comparison
function commonPrefix(words) {
  const first = words[0];
  for (let i = 0; i < first.length; i++) {
    for (const w of words) {
      if (i >= w.length || w[i] !== first[i]) return first.slice(0, i);
    }
  }
  return first;
}

Scan columns left to right. The first mismatch or short word ends the common prefix.

Complexity: O(total characters) time, O(1) space. Each character is compared at most once.

Common mistakes: Not handling a word shorter than the first.

P25. Same Letters, Different Order

Frequency map up and down
function isAnagram(a, b) {
  if (a.length !== b.length) return false;
  const counts = new Map();
  for (const ch of a) counts.set(ch, (counts.get(ch) || 0) + 1);
  for (const ch of b) {
    const c = counts.get(ch) || 0;
    if (c === 0) return false;
    counts.set(ch, c - 1);
  }
  return true;
}

Equal lengths + every character of b "uses up" a matching character of a means the counts are identical.

Complexity: O(n) time, O(k) space. k distinct characters in the map.

Common mistakes: Only checking that every char of b exists in a (ignores counts).

P26. Integer Square Root

Binary search on the answer
function sqrtFloor(x) {
  let lo = 0, hi = x, ans = 0;
  while (lo <= hi) {
    const m = Math.floor((lo + hi) / 2);
    if (m * m <= x) {
      ans = m;
      lo = m + 1;
    } else {
      hi = m - 1;
    }
  }
  return ans;
}

The yes/no question "is m² ≤ x?" is true for small m and false for large m. Binary search finds the last "yes".

Complexity: O(log x) time, O(1) space. The candidate range halves each step.

Common mistakes: Returning lo instead of the last valid m; Off-by-one on perfect squares.

P27. First Position of a Value

Binary search that keeps going left
function firstOccurrence(nums, target) {
  let lo = 0, hi = nums.length - 1, ans = -1;
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (nums[mid] === target) {
      ans = mid;
      hi = mid - 1;
    } else if (nums[mid] < target) {
      lo = mid + 1;
    } else {
      hi = mid - 1;
    }
  }
  return ans;
}

A match is recorded, then the search continues left in case an earlier copy exists.

Complexity: O(log n) time, O(1) space. Still halves the range each step.

Common mistakes: Returning immediately on the first match; Walking left linearly after a match (O(n) worst case).

P28. Pair With Target (Unsorted)

Complement lookup map
function twoSum(nums, target) {
  const seen = new Map();
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];
    seen.set(nums[i], i);
  }
  return [-1, -1];
}

The map turns "search for a partner" into a constant-time lookup. Checking before inserting prevents pairing an element with itself.

Complexity: O(n) time, O(n) space. One pass; the map can hold n entries.

Common mistakes: Inserting before checking (pairs x with itself when 2x = target); Sorting first (loses the original indexes).

P29. Pair With Target (Sorted)

Opposite-end pointers on sorted data
function pairSumSorted(nums, target) {
  let l = 0, r = nums.length - 1;
  while (l < r) {
    const s = nums[l] + nums[r];
    if (s === target) return [l, r];
    if (s < target) l++;
    else r--;
  }
  return [-1, -1];
}

Sorted order tells you which pointer to move: moving left up increases the sum, moving right down decreases it.

Complexity: O(n) time, O(1) space. Each step discards one candidate.

Common mistakes: Moving both pointers at once; Using l <= r (pairs an element with itself).

P30. Best Window of Size K

Fixed-size sliding window
function maxSumK(nums, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  let best = sum;
  for (let i = k; i < nums.length; i++) {
    sum += nums[i] - nums[i - k];
    if (sum > best) best = sum;
  }
  return best;
}

Each slide is O(1): add the entering element and subtract the leaving one.

Complexity: O(n) time, O(1) space. Each element enters and leaves the window once.

Common mistakes: Starting best at 0 (wrong for all-negative input); Off-by-one on nums[i - k].

P31. Longest Stretch Without Repeats

Variable sliding window + set
function longestUnique(s) {
  const inWindow = new Set();
  let l = 0, best = 0;
  for (let r = 0; r < s.length; r++) {
    while (inWindow.has(s[r])) {
      inWindow.delete(s[l]);
      l++;
    }
    inWindow.add(s[r]);
    best = Math.max(best, r - l + 1);
  }
  return best;
}

The window grows on the right and shrinks on the left only as much as needed to stay valid.

Complexity: O(n) time, O(k) space. Each character is added and removed at most once; k = alphabet size.

Common mistakes: Resetting the window completely on a repeat (misses "dvdf"); Using if instead of while when shrinking.
